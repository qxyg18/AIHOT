## 二、「实时更新」拆成三层，避免目标错配

| 层 | 现状 | 要不要做 |
|---|---|---|
| L1 数据实时（后端出内容） | 已是分钟级调度 + 小时级成稿，日报每日一期 | **不建议追秒级**。行业情报按小时级已足够，再压缩只堆模型调用量 |
| L2 打开即新（展示） | 页面缓存 60~600 秒，刷新一下即最新 | **默认够用**。只有要求「页面停着不动也自动更新」才需改前端（轮询/SSE），属框架代码改动 |
| L3 主动推（触达） | 通道骨架在，地址未配 | **这才是手机上最有价值的一层**，成本最低、体感最强 |

## 三、五条路径与利弊

| 路径 | 做法 | 利 | 弊 |
|---|---|---|---|
| **A 局域网直连** | 手机连同一 WiFi，开 `http://192.168.2.22:3000` | 0 成本、30 分钟、数据不出内网、管理面不外露 | 仅同网可达；PC 关机即断；内网 IP 会变 |
| **B 内网穿透**（推荐主力） | 隧道服务把本机站点映射到公网 | 随时随地可用、免公网 IP、免备案、半天落地 | 多一个常驻服务要维护；PC 仍需常开；穿透服务是外部依赖 |
| **C 上云托管** | 租 2 核 4G 轻量服务器，整站搬迁 | 唯一能摆脱 PC 常开；24h 在线；响应快 | 要迁 3 个 docker 卷、需割接；月租；对外服务要备案；采集与站点关系要重新理顺 |
| **D 发布为应用** | 用发布能力上线 | 0 成本、有公网链接 | 本站是 db+api+worker+web 四容器且有 Postgres，不是单端口应用；只适合发布「日报只读快照」这类切片 |
| **E 推送到手机**（推荐搭配） | 新精选生成后推 webhook 到钉钉 | 手机零门槛（不记 IP、不装 App）；体感最接近实时；2 小时可落 | 只能看推送内容、不能逛站；依赖 PC 跑任务；内容留在群里 |

### B 的三个子选型

| 方案 | 特点 | 适用 |
|---|---|---|
| Cloudflare Tunnel | 免费、自带 HTTPS、可用 Cloudflare Access 做邮箱白名单（免费） | 想省心、能接受配置一个 CF 账号 |
| Tailscale / ZeroTier | 手机装 App 组虚拟内网，**不向公网暴露任何端口**，安全性最高 | 只要自己看、不在意多装一个 App |
| frp / 花生壳 / ngrok | frp 需自备公网 VPS；花生壳要实名且带宽小；ngrok 免费域名会轮换 | 已有公网 VPS 才考虑 |

## 四、风险与红线（按严重度）

1. **管理面同域暴露（最高）**：`/admin` 有登录保护，但一旦公网可达，等于把登录页挂到公网任人爆破，且同域下还有 LLM key 配置页与预算页。**任何公网方案必须先加一层前置访问控制**（Cloudflare Access 白名单 / Tailscale 组网 / 反代 Basic Auth + IP 白名单）。这条不做，不要上公网。
2. **PC 常开是隐藏前提**：A / B / E 全部依赖这台 PC 开机且 Docker 在跑。Docker Desktop 在 Windows 上默认不随开机自启，重启后容器没起来手机端全黑。需补开机自启 + 健康检查。
3. **内网 IP 会漂**：`192.168.2.22` 是 DHCP 分配，路由器重启或续租可能变化。要么做 DHCP 保留，要么走穿透方案（穿透不依赖内网 IP）。
4. **实时性的期望管理**：页面缓存 60~600 秒，打开即最新最多差几分钟。要做到「停着自动刷新」必须改前端，属可选增强。
5. **IPv6 直连不可行**：网卡虽有公网 IPv6 地址，但实测出网不通，别在这条路上消耗时间。
6. **D 方案慎用整站**：把内部情报台挂到公网链接有被索引、被扫描的风险，且后台同域。

## 五、推荐落地顺序

1. **第 0 步（今天，约 30 分钟）**：A 局域网直连 + 手机加主屏书签，先确认手机端实际观感；给 PC 做 DHCP 保留或确认防火墙对局域网放行。
2. **第 1 步（本周内）**：B 二选一落地。想省心选 Cloudflare Tunnel + Access 白名单；想最安全选 Tailscale。
3. **第 2 步（与 B 同期）**：E 钉钉推送。框架已有 webhook 投递骨架，补一个钉钉格式适配器即可，让「有新内容就推手机」成立。
4. **暂不做**：C 上云、D 发布整站。
5. **可选增强**：加 PWA manifest + Service Worker，支持「添加到主屏幕」全屏体验，改动仅数个文件。

## 六、待定夺

1. 穿透方案选哪条？（Cloudflare Tunnel / Tailscale / 其他）
2. 推送走钉钉，还是这一版先不做？
3. 手机端要求是「能看」还是必须「页面停着也自动更新」？后者需改前端。

# 附录三：内网穿透 · 风险与收益详解（2026-10-03）

## 结论：不在局域网照样能看

穿透的本质是把「只有同一 WiFi 能访问的内网地址」变成「任何网络都能访问的地址」。手机切 4G/5G、公司网络、外地出差都能直接打开。这是穿透相对局域网直连的唯一增量价值，也是它存在的全部理由。

## 三种机制，风险差很远

| 机制 | 需要公网 IP | 动路由器 | 暴露面 | 适用 |
|---|---|---|---|---|
| 反向隧道（Cloudflare Tunnel / ngrok / frp） | 否 | 否 | 有一个公开域名，靠访问控制挡 | 要分享给他人 |
| **组网 VPN（Tailscale / ZeroTier）** | 否 | 否 | **几乎为零**，仅授权设备可达 | **自用首选** |
| 端口映射（路由器转发 / DMZ ＋ DDNS） | 是 | 是 | PC 直接裸奔公网 | 不建议 |

前两种都是**本机主动向外出连接**，所以不依赖公网 IP、不用改路由器，家里宽带是不是 CGNAT 都无影响。第三种才会连带暴露家里内网的其他设备。

## 收益（六条）

1. **不在任何局域网也能看** —— 核心收益。
2. **零成本**。Cloudflare Tunnel 免费；Tailscale 个人版（2026-04 改版后）永久免费：6 个用户、**每用户设备数不限**、50 个标签资源，仅限非商业用途。
3. **不碰运营商**：不需要公网 IP，不需要 ICP 备案（穿透服务在境外，站点也不对外提供公开服务）。
4. **数据不出本机**：数据库、模型 key、内容全部留在这台 PC，穿透只转发 HTTP 请求。
5. **与本地状态完全一致**：本机改完手机立刻可见，无需任何同步。
6. **半天落地**：装一个客户端 + 配一次，之后不用管。

## 风险（按严重度）

**1. 后台管理面同域暴露 —— 最高，且是唯一的硬红线**

公开可达后等于把 `/admin` 登录页挂到公网，同域下还有 LLM key 配置页、预算页、审计日志。

实测缓解措施（比预想的好）：

- `apps/api/src/routes/admin-auth.ts` 有速率限制——**单 IP 每 15 分钟最多 10 次、全局每 15 分钟最多 50 次**；
- `packages/backend/src/admin/auth.ts` 用 `timingSafeEqual` 常数时间比对，密码强制 ≥12 位。

但仍是**单因素密码**，且限流是内存态、进程重启即清零，无递增锁定。因此这条红线不因限流而解除：

- 选 Cloudflare Tunnel → 必须同时配 **Cloudflare Access** 邮箱白名单
- 选 Tailscale → 天然满足
- 两种都不要走端口映射

**2. 这台 PC 成为单点**

穿透只是转发，站点仍跑在本机。关机 / 蓝屏 / Windows 更新重启 / Docker Desktop 未随开机自启 → 手机端全黑。这是穿透相对上云的根本劣势：可用性取决于你家的电、网、机器。

**3. 流量经过第三方**

反向隧道的 HTTP 请求经服务商边缘节点转发。主流服务商做 TLS 透传（看不到明文），但元数据（谁、何时、访问了什么）在对方手里。Tailscale 是 WireGuard 端到端加密点对点，此风险基本为零。

**4. 免费服务的不确定性**

Cloudflare Tunnel 免费且稳，国内偶发抖动；ngrok 免费域名重启会变，不适合长期；来源不明的免费穿透服务等于把内网机器交给别人，禁用。

**5. 被扫描是必然**

公网可达即进入扫描器视野，只是时间问题。所以访问控制是前置条件，不是可选项。

## 底线：用穿透必须同时做三件事

1. 加前置访问控制（Cloudflare Access 白名单，或 Tailscale 组网）
2. 给 PC 配开机自启 + 健康检查（Docker Desktop 默认不随开机启动）
3. 内网 IP 做 DHCP 保留（穿透本身不依赖内网 IP，但局域网那条路会用到）

## 与本人情况的匹配

- **只有自己看 → Tailscale**：安全等级最高、配置最少，手机装个 App 即可。
- **要分享给同事 → Cloudflare Tunnel ＋ Access 白名单**：同事不用装任何东西，加白名单就行。

两者都不花钱、不需要备案、不需要公网 IP。
