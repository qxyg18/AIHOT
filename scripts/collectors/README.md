## 组成

| 件 | 作用 |
|---|---|
| `run_collect.py` | 调度器：高德=**夜档（01:00-06:00）**增量补坐标+失败重试+每月 1-3 日窗口全量刷评分（窗口外即刻跳过，`AMAP_FORCE=1` 手动强跑）；点评=探针一次+每小时滴灌；无凭据静默跳过。锁记 pid：持有者已死立即接管（防假死空跑） |
| `collect_amap.py` | 高德 v3 place/text（POI 搜索）：坐标+评分+地址+营业时间，逐条落盘中断零损失，配额到顶提前收工明晚续跑 |
| `collect_amap_expand.py` | 三类词+品类词扩充引擎（品牌/品类/集团/mall-cat 场景⑦），断点续跑+30 天滚动重扫；夜档额度按 `night_allowance()`（10-14 凌晨一次性 20000；此后常态月更窗 80/平日 2000）共享封顶（`nightUsed` 记账） |
| `mem_watchdog.pyw` | 内存看门狗：工作集超限/系统可用<600MB 兜底杀采集器保机，两种击杀后都清孤儿 run.lock（调度自动续跑） |
| `collect_dianping.py` | 点评采集：**每小时一轮、每轮 10 家**（09-30 深夜命主令），25 秒间隔+抖动，全量 419 家约 42 轮 ≈ 两天覆盖一圈；探针先行存原始页供解析层开发；城市表=resolve_city_ids.py 解析的 84 城（state/city-ids.json） |
| `resolve_city_ids.py` | 一次性工具：从各城市首页解析点评数字 cityId，产出 state/city-ids.json（内置表仅上海=1/北京=2 实测确认，其余以 sidecar 为准） |
| `out/mall-coords.json` | 产物：slug -> POI 档案（poi_id/坐标/评分/地址/营业时间）。**并入种子是独立人工审过的步骤，本管线不改种子** |
| `out/dianping/` | 点评原始页存档（解析层待真实样本定形后，从这里提取评分/评论数/品牌清单） |
| `state/`、`logs/` | 运行状态与日志 |

## 调度

`schtasks radar-merchant-collect` **每小时 :15** 跑 `run_collect.py`（系统级，ZCode 不在线也跑）；
高德段只在 **01:00-06:00** 实跑（命主 2026-10-13 夜档令），窗口外即刻跳过并放行点评滴灌；
夜档额度=引擎单源 `night_allowance()`（10-14 凌晨一次性 20000 追进度；此后恢复常态：月更窗 1-3 日 80、
其余 2000/晚；同晚续跑累计共享——2026-10-13 命主晚修订令，收回原"每晚 20000"常设口径）。
月度巡检自动化（ZCode，每月 1 日 05:30）读 state/logs 判读异常并上报。
